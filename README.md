# Gym희제 v1.1

세트마다 다른 중량과 반복 횟수를 기록하는 개인용 PWA입니다. 로그인이나 서버 저장 없이, 사용하는 기기의 브라우저에 기록합니다.

## 사용할 수 있는 기능

- 등 → 어깨 → 가슴 → 하체 → 팔 순서의 기본 운동 14종
- 세트별 중량 ±5, 반복 ±1, 숫자 직접 입력
- 바로 앞 세트 복사 추가, 세트 삭제와 5초 실행 취소
- 운동마다 kg/lb 선택
- 저장 버튼으로 전체 설정 확정, 최종 값이 같으면 기록을 추가하지 않음
- 현재 설정과 별도로 이전 설정 최대 5개 표시. 더 오래된 기록도 내부 보관
- 사용자 운동 추가, 이름·분류 수정
- 기본·추가 운동 모두 상세 화면 상단의 ‘운동 삭제’로 삭제 가능
- 첫 준비 완료 후 오프라인 조회·저장·재실행

기본 운동의 실제 중량과 반복은 비워 두었습니다. 문서와 화면 캡처에 등장하는 숫자는 **검증용 예시**이며 실제 앱의 초기 기록이 아닙니다.

## 운동 삭제 방법

목록에서 운동을 선택한 뒤 제목 아래 **운동 삭제**를 누릅니다. 확인 창의 **운동 삭제**를 한 번 더 누르면 그 운동과 해당 운동의 과거 기록만 삭제됩니다. 취소하면 기존 기록과 편집하던 값이 남습니다. 삭제한 기본 운동도 앱 재실행·업데이트 때 다시 생기지 않습니다. 실제로 삭제를 확정한 기록은 되돌릴 수 없습니다.

## 앱 수정과 내 기록

**동일한 앱 주소와 저장 공간에서 앱을 업데이트하면 운동 정보는 유지됩니다.**

화면 파일과 운동 데이터의 저장소를 분리했고, 앱 시작 시 매번 기록을 초기화하지 않습니다. 업데이트 시 기본 운동을 덮어쓰지 않으며 추가한 운동·중량·반복·히스토리를 유지합니다. 다른 창에서 편집 중인 값도 업데이트 수락 창 때문에 강제로 새로고침되지 않도록 했습니다.

v1.0 → v1.1은 기존 DB 이름과 형식 버전을 그대로 사용하므로 기록을 옮기거나 새로 입력할 필요가 없습니다. 이후 개발에서도 [데이터 보존 규칙](docs/DATA_MODEL.md)을 따르고, 구버전 앱으로 만든 기록을 업데이트 후 비교하는 검증을 유지합니다.

단, 다음은 앱 업데이트와 다른 상황입니다.

- 사이트 데이터를 사용자가 삭제한 경우
- 다른 기기 또는 다른 브라우저를 사용하는 경우
- 주소의 도메인·프로토콜·포트가 달라지는 경우
- 시크릿 모드 종료 또는 브라우저가 저장 공간을 회수한 경우

이 경우 기록이 자동 이전되거나 복구된다고 보장할 수 없습니다. v1에는 백업·복원·클라우드 동기화가 없습니다. 배포 주소를 정한 뒤 그 주소를 계속 사용하는 것이 좋습니다.

## PC에서 실행

Node.js가 설치된 컴퓨터에서 이 폴더를 터미널로 연 뒤 실행합니다. 검증 환경은 Windows / Node.js 24.12.0 / npm 11.6.2입니다.

```sh
npm ci
npm run dev
```

개발 미리보기: `http://127.0.0.1:5173/`

PWA·오프라인 기능은 개발 서버가 아닌 다음 배포용 미리보기에서 확인합니다.

```sh
npm run build
npm run preview
```

배포용 미리보기: `http://127.0.0.1:4173/`

개발용 5173과 배포 검증용 4173은 **서로 다른 저장 공간**입니다. 테스트 브라우저도 별도 저장 공간을 사용합니다. 한 곳에서 입력한 값이 다른 곳으로 자동 복사되지는 않습니다.

`index.html`을 파일 탐색기에서 직접 여는 방식은 지원하지 않습니다. 실행 중인 서버를 종료하면 PC의 미리보기 주소도 닫힙니다. 이 주소는 해당 PC에서만 접속할 수 있으며 휴대폰 설치용 공개 주소가 아닙니다.

## 휴대폰에 설치할 배포 파일

GitHub Pages 자동 배포 설정은 `.github/workflows/deploy-pages.yml`에 준비했습니다. 최초 설정과 아이폰 홈 화면 추가 방법은 [GitHub Pages 배포 안내](docs/GITHUB_PAGES.md)를 참고하세요. 공개 주소는 `https://nigasaa.github.io/gym-heeje/`이며, 배포 상태는 저장소 Actions에서 확인할 수 있습니다.

`dist/` 안의 내용을 HTTPS 정적 호스팅에 올리면 됩니다. 루트 주소뿐 아니라 `/gym-heeje/` 같은 하위 경로도 사용할 수 있게 상대 경로로 만들었습니다.

배포 시 지킬 사항:

1. `dist`의 **내용 전체**를 올립니다. 앱 소스·node_modules·테스트 자료는 올리지 않습니다.
2. HTTPS를 사용하고 앱 주소를 유지합니다. 기록을 계속 쓰려면 도메인·프로토콜·포트를 함부로 바꾸지 않습니다.
3. `sw.js`, `index.html`, `manifest.webmanifest`는 장기간 변경 불가 캐시로 설정하지 않습니다. 해시가 있는 JS/CSS 파일은 장기 캐시가 가능합니다.
4. `manifest.webmanifest`는 `application/manifest+json`, JS는 올바른 JavaScript MIME 타입으로 제공합니다.
5. 정상 접속 후 ‘오프라인 사용 준비 완료’를 확인합니다.
6. iPhone Safari는 공유 메뉴의 ‘홈 화면에 추가’, Android Chrome은 ‘앱 설치’ 또는 ‘홈 화면에 추가’를 사용합니다. 메뉴 이름은 OS·브라우저 버전에 따라 다를 수 있습니다.
7. 실제 폰에서 기록을 입력하고 앱 종료·재실행·비행기 모드 재실행을 확인합니다.

현재 외부 호스팅에는 공개 배포하지 않았습니다. 호스팅 대상이 정해지면 준비된 `dist`를 배포할 수 있습니다. 실제 iPhone/Android 설치 검증은 별도 수동 체크가 필요합니다.

## 기록 규칙

`50×10 · 50×10 · 55×8 · 55×8`은 독립된 세트 4개입니다. 같은 값도 합치지 않습니다. 세트 수 입력란과 별도 세트 수 저장 필드는 없습니다.

세트 추가는 마지막 세트를 복사하되 새 식별자를 만듭니다. 마지막 세트도 삭제할 수 있지만 빈 구성을 저장하려면 최소 1세트를 다시 입력해야 합니다. 중량 0~9999.99, 소수점 최대 2자리, 반복 1~999를 허용합니다.

단위 변경은 숫자를 자동 환산하지 않습니다. 과거 기록은 저장 당시 단위를 유지합니다. 이름·분류만 변경하면 운동 설정 히스토리는 추가되지 않습니다.

저장 전 변경은 메모리에만 있습니다. ‘저장’을 누르기 전에 앱을 강제 종료하면 해당 수정은 복구되지 않습니다. 정상적인 화면 이동에는 저장·폐기·계속 편집 선택을 제공합니다.

## 프로그램 구조

| 위치 | 역할 |
|---|---|
| `src/domain` | 세트 모델, 입력 검증, 변경 비교, 값 계산 |
| `src/data` | 기본 5분류·14종 운동 |
| `src/storage` | IndexedDB 초기화, 조회, 저장·삭제 트랜잭션, 충돌 검사 |
| `src/services` | 입력을 저장 계약으로 변환, 저장 공간 유지 요청 |
| `src/screens` | 메인, 상세·추가, 정보 수정 |
| `src/components` | 세트 편집기, 숫자 조절, 이탈 확인창 등 |
| `src/pwa` | 설치 안내, 오프라인 준비와 업데이트 처리 |
| `src/styles` | 반응형 화면·터치 영역·확대 대응 |
| `tests` | 규칙·저장·화면 테스트와 브라우저 검증 |
| `docs` | 데이터 모델, 테스트 결과, 휴대폰 확인 절차와 예시 캡처 |

React 19.3.0, TypeScript 7.0.2, Vite 8.3.1, idb 8.0.3, vite-plugin-pwa 1.3.0을 사용했습니다. 정확한 의존성은 package-lock.json에 고정되어 있습니다.

## 테스트 실행

```sh
npm test
npm run test:e2e
```

`test:e2e`는 타입 검사, 정식 빌드와 업데이트 검증용 빌드, 미리보기 서버 준비, 브라우저 테스트를 순서대로 실행합니다. 테스트 저장 데이터는 분리된 임시 브라우저에서만 생성합니다. 기존 사용자 브라우저의 기록은 초기화하지 않습니다.

현재 브라우저 테스트는 Windows의 Microsoft Edge와 Playwright WebKit을 사용합니다. 필요한 WebKit을 설치하려면:

```sh
npx playwright install webkit
```

현재 작업 환경에 내려받은 `work/browsers`가 있으면 테스트 실행기가 그 경로를 자동 사용합니다. 없으면 Playwright 기본 경로를 사용합니다. 다른 운영체제에서는 `playwright.config.ts`의 Edge 채널 설정을 해당 환경의 Chromium으로 조정해야 합니다.

테스트 결과와 임시 업데이트 빌드는 이 프로젝트 바깥의 `../../work/`에 둡니다. 이 경로는 앱 데이터를 보관하는 곳이 아닙니다. 결과 요약은 [검증 결과](docs/VALIDATION.md)를 참고하세요.

## 아이콘과 디자인

밝은 청회색 바탕, 짙은 글자, 파란 조작 버튼을 사용했습니다. 기본 시스템 글꼴을 사용하므로 외부 폰트 연결이 필요 없습니다. 바벨 모양 앱 아이콘은 이 프로젝트에서 작성한 SVG를 PNG로 변환한 것입니다.

```sh
npm run icons
```

아이콘을 바꾼 뒤에는 다시 빌드합니다. 설치된 앱 이름·아이콘의 갱신 시점은 플랫폼에 따라 다를 수 있습니다.
