# Gym희제 v1.1 검증 기록

## v1.1.1 모바일 4세트 표시 수정

2026-10-01: 단위 검사 59개 통과. Edge·WebKit 브라우저 검사 24개 중 21개 통과, 기존 도구 제한에 따른 제외 3개, 실패 0개.

- [Apple 화면 규격](https://developer.apple.com/kr/design/human-interface-guidelines/layout)의 iPhone 16 Pro 402×874를 포함해 390·402·430px에서 각 세트의 위치와 카드 내부 경계를 확인했다.
- `40×12 · 40×12 · 50×10 · 50×8`, 세 자리 중량, 소수 중량 `100.5 / 125.5`를 포함한 네 조합의 4세트가 모두 같은 줄에 있고 가로 잘림이 없었다.
- 200% 글자 확대 시 값을 숨기지 않고 줄바꿈하며 페이지의 가로 넘침이 없었다. 데스크톱의 숫자 크기는 기존 23px이었다.
- 기존 저장소 보존, 명시적 운동 삭제, 구버전 데이터에서 새 버전 적용, 다른 창의 편집 유지, 오프라인 저장 검사를 통과했다. DB 이름·버전·저장 데이터 구조는 변경하지 않았다.
- 실물 iPhone에서의 확인은 아직 하지 않았으며 자동화된 Edge·WebKit 화면 검증 결과이다.
- [v1.1.1 배포 실행](https://github.com/nigasaa/gym-heeje/actions/runs/36870629778)은 검사와 배포 모두 성공했다. 공개 주소의 v1.1.1을 402×874 임시 Edge 컨텍스트에서 다시 열어 4세트 한 줄 표시·오프라인 저장·삭제를 확인했다. 오류와 외부 요청은 없었다.

검증 환경: 2026-09-29, Windows, Node 24.12, Edge와 Playwright 1.63 WebKit. 브라우저마다 별도의 임시 저장 공간을 사용했다. 스크린샷의 중량은 테스트 예시이며 실제 앱 초기 데이터에는 포함되지 않는다.

## 구현 및 검증 범위

- TypeScript 검사와 배포 빌드 통과.
- 단위·저장소·컴포넌트 테스트 59개 통과.
- 브라우저 검사 22개 중 19개 통과, 3개 제외, 실패 0개. 제외 사유는 아래에 기록했다.
- 브라우저 검증: 기본 목록, 독립 세트 편집, 복사/삭제/취소, 저장과 무변경, 최근 5개, 사용자 운동 관리, 뒤로 가기, 충돌 처리, 작은 화면을 검사한다.
- Edge에서 실제 서비스 워커 새 버전을 적용해 기존 40×12 저장값 보존을 확인했다. 다른 창의 미저장 55 입력도 강제 새로고침 없이 유지됐다. 다른 앱의 테스트 캐시도 남았다.
- 실제 v1.0 빌드에서 입력한 기본·사용자 운동, 단위, 소수 중량, 전체 과거 이력을 v1.1 적용 후 모든 필드로 비교하여 일치함을 확인했다.
- v1.1에서 기본 운동을 삭제한 뒤 추가 업데이트를 적용해 삭제 상태와 나머지 기록 보존을 확인했다. 기본 운동 삭제 실패 시 삭제 표시까지 롤백되는 것도 확인했다.
- Edge·WebKit 모두 눈에 보이는 삭제 버튼, 확인 취소 시 미저장 입력 유지, 확인 후 해당 운동만 삭제, 재실행 후 삭제 유지 검증을 통과했다.
- Edge에서 준비 후 오프라인 재실행·수정·저장·다시 실행을 확인했다.
- 320/360/390/430px, 긴 이름, 50세트, 주요 버튼 48px, 200% 글자 확대를 검사했다.

## 2026-10-01 공개 배포 검증

- [GitHub Actions 배포](https://github.com/nigasaa/gym-heeje/actions/runs/36866651849): 단위 검사 59개, Chromium 브라우저 검사 11개 통과, build·deploy 성공.
- 로컬 Edge 브라우저 검사 11개 통과. 오프라인 저장 테스트는 저장값이 메인 화면에 표시된 뒤 새로고침하도록 순서를 명확히 했다.
- [공개 앱](https://nigasaa.github.io/gym-heeje/)을 빈 임시 Edge 컨텍스트에서 390×844 터치 화면으로 확인했다. 기본 운동 14종과 분류 순서가 일치했다.
- HTTPS 페이지·manifest·아이콘 3종·Apple 아이콘·서비스 워커 모두 200 응답. manifest id·scope는 `./`, 서비스 워커 범위는 `/gym-heeje/`이다.
- 검증용 운동의 `40×12 · 55×8` 저장 후 오프라인에서 `45×12 · 55×8`로 수정·저장·재실행하여 값과 이전 이력을 확인했다. 삭제 확인 후 해당 운동만 제거되고 기본 운동 14종이 유지됐다.
- 공개 앱의 스크립트 오류·실패 응답·앱 외부 요청 0개. 실제 사용자 브라우저나 기록은 사용하지 않았다.

## 미확인 사항과 자동화 제한

실제 iPhone/Android 홈 화면 설치, OS 종료 후 재실행, 물리 키보드 화면 변화는 아직 확인하지 않았다. 따라서 설치 완료 또는 실기기 검증 완료로 판단하지 않는다. HTTPS 공개 호스팅과 공개 주소에서의 Edge 오프라인 사용은 위 검증으로 확인했다.

Playwright 1.63의 WebKit은 오프라인 모의 실행 시 서비스 워커 응답에도 내부 오류가 발생한다. 이 현상은 [공식 이슈 #42775](https://github.com/microsoft/playwright/issues/42775)에 보고되어 있다. 해당 테스트는 실패를 숨겨 통과시키지 않고 WebKit에서 제외했다. WebKit 업데이트 수명주기 검사와 중복 화면 캡처도 제외하여 총 3개 제외 항목이 있다. Safari의 실제 오프라인 동작은 아래 실기기 점검이 필요하다.

## 배포 후 실기기 점검 순서

1. 결정된 HTTPS 주소에서 앱을 열어 오프라인 준비 완료를 확인한다.
2. 홈 화면에 설치하고 이름·아이콘·독립 실행을 확인한다.
3. 테스트 운동을 추가하여 서로 다른 중량 4세트를 저장한다.
4. 비행기 모드에서 앱 종료/재실행 후 조회·수정·저장하고 다시 연다.
5. 숫자 키보드를 열어 마지막 세트와 저장 버튼에 접근 가능한지 확인한다.
6. 같은 주소에 새 버전을 올려 업데이트 후 운동과 과거 기록이 유지되는지 확인한다.
7. 테스트 운동만 삭제한다. 사이트 데이터 전체 삭제는 하지 않는다.

기존 DB를 지우는 업데이트 코드가 없으며 기본 운동은 최초 초기화에만 삽입된다. 향후 데이터 모델이 바뀔 때에는 기존 기록을 변환하는 이전 절차와 검증을 추가해야 한다. 브라우저 데이터 삭제·기기 이전을 위한 백업/동기화는 현재 범위 밖이다.
